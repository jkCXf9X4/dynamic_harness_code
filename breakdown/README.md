# Product Breakdown — dhc

dhc's systems-engineering record: **current state** in the seven-layer tree
below, **history** in the dated decision stream (`decisions/`), and
**generated registers** indexing both. For authors and agents navigating dhc.

## The Seven Layers

- [`00-intent/`](00-intent/README.md) — why dhc exists: mission, goals, scope, boundaries.
- [`01-product/`](01-product/README.md) — what is promised: capabilities and requirements others rely on.
- [`02-architecture/`](02-architecture/README.md) — how the parts fit and how the harness organizes work: concurrency, completion dispatch, cancellation, event-stream resolution, the boundary event log, delegation, peer exchange, and each agent's own execution.
- [`03-implementation/`](03-implementation/README.md) — where it lives: modules, files, code layout, code-level facts.
- [`04-verification/`](04-verification/README.md) — how we know: test strategy, acceptance criteria, evidence.
- [`05-operation/`](05-operation/README.md) — how it runs: install, quick start, entry points, demos, runbooks.
- [`06-evolution/`](06-evolution/README.md) — what might change: IMP candidates (selected → implemented); never current state.
- `decisions/` — why it changed: the flat, dated decision stream — history, never current state.

Code, tests, and examples sit outside this tree; `pb.toml` scopes what counts.

## Boundary Rule

A fact's home is the layer whose question it answers; information flows
downward only. Current state lives in exactly one layer leaf; history lives
in `decisions/` records; tracking lives in an IMP's `status:`. When the
guides disagree, this README's rule wins.

## Reading Order

1. Start here, then the layer README, then the one leaf owning the concern.
2. A layer README's `## Contents` rows carry each leaf's id and one-line
   summary — route without opening files.
3. Stop when the fact is found; never read on "for context".
4. History: the decision archive via its index
   (`docs/archive/decisions/README.md`), then the one
   record — never whole-directory reads.

## Citation Vocabulary

- `INFO-xxx` — state leaves, one concern each.
- `AD-` / `PD-` / `IMD-` / `VD-` / `OD-` — decision records by layer:
  architecture, product, implementation, verification, operation.
- `TC-` — task contracts. `IMP-` — improvement candidates (`06-evolution/`:
  selected → implemented).
- Records and leaves are cited by id, never by path.
- Legacy: `D1`–`D5` → `AD-001..005`; `G-xx` → `PD-001`; `H-xx` → `AD-007` /
  `IMD-003` / `PD-002` / `IMD-004`.

## Routing an Edit

- Current-state fact ("X is …") → its layer leaf.
- Dated choice or event ("on 2026-10-07, X changed") → a `decisions/` record.
- Open item or progress → the IMP's `status:`, never a leaf.
- Idea → an IMP candidate under `06-evolution/selected/`.
- Full protocol: the `product-breakdown` skill
  (`.agents/skills/product-breakdown/guidelines/storage-rules.md`).

## Registers

`docs/archive/decisions/README.md`, `docs/archive/design-choice-log.md`,
and `docs/archive/traceability-map.md` are
generated by release builds (`pb registers`) and stripped between them —
never hand-edit.
